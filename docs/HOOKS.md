# Hooks and quality gates

Codex 0.163.0 declares `hooks stable true`. [hooks.json](codex/hooks.json) was prepared and an identical copy was installed at `.codex/hooks.json` through the environment's write permission. Only the edit `PostToolUse` is configured, for the lightweight gate; no global hooks are modified. The reviewed template does not prove automatic loading: installation, project trust and per-event execution must be confirmed separately in a session that loads the configuration.

| Gate             | Moment and check                                                                                   | Cost and limitation                                                                                                 |
| ---------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| A · file quality | After a TS increment: formatting, lint and typecheck with the real package.json scripts            | Do not build the whole application after every edit; failures stop integration                                      |
| B · shaders      | After editing GLSL: build for imports; WebKit browser for compilation and WebGL errors             | No `glslangValidator`; the build does not prove valid GLSL syntax                                                   |
| C · visual       | After a visual stage: Playwright captures modes, interaction and mobile; record viewport and state | On demand, with a local server; no Chrome; without approved baselines do not claim an approved reference comparison |
| D · pre-commit   | Run the full gate and the sensitive-file review before any eventual commit                         | No commit is authorized; pattern scanning does not certify the absence of secrets                                   |
| E · completion   | Review `ACCEPTANCE.md`, relevant tests, evidence and limitations                                   | Do not mark a blocked item as complete                                                                              |

The equivalents defined in `package.json` are `npm run quality:file` (formatting, lint and typecheck), `npm run quality:shader` (build and visual error validation), `npm run quality:precommit` and `npm run quality:completion` (check, tests and sensitive scan). Execution results are kept in `ACCEPTANCE.md` to avoid confusing an intention with an executed validation. Scripts must propagate the failure code; wrappers that return success by skipping a missing tool are not allowed. Automation must not open personal profiles, reinstall dependencies, publish or call Codex again; this avoids recursion and loops.

The exact matcher is `^(apply_patch|Edit|Write)$`; it runs `node scripts/hook-quality.mjs` with a 30-second timeout. This relative command requires starting the session at the project root. It does not use a `CODEX_PROJECT_DIR` variable, which does not exist in the documentation consulted. Expensive and visual gates remain explicit; the hook does not run a build or open a browser.

Handler contract: read one JSON object from stdin, not shell arguments derived from the edited content. The relevant fields are `hook_event_name`, `cwd`, `tool_name`, `tool_input` and `tool_response`. In Codex, `apply_patch` arrives as `tool_input.command` and keeps the canonical name even if it matches through the Edit/Write alias. For tools with `file_path`, check it before resolving paths. A non-TS event must not trigger expensive validation. Failures must produce visible feedback with exit code 2 and stderr; do not revert an edit that was already made.

The structure was checked against [HookHandlerConfig, HooksToml and MatcherGroup of the schema pinned to 0.163.0](https://raw.githubusercontent.com/openai/codex/rust-v0.163.0/codex-rs/core/config.schema.json) and the stdin protocol against [the official documentation](https://learn.chatgpt.com/docs/hooks). JSON parsing and the template's fields were checked, without claiming automatic validation of the whole schema. The handler is verified separately with test events; native activation requires evidence of loading and a real event.

Handler validation executed: `node scripts/verify-hook.mjs` checked a non-TS event (skip), invalid JSON (exit 2) and a TS patch (ran quality:file successfully). Native configuration installed, but its automatic loading by event in this already-open session has not been observed; it requires the next trusted project session. Trust is not changed automatically.
